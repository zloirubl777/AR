# ПОЛИГОН 02.6 — восстановление комнаты для дуэли без маркера

## Исправления
- Создание комнаты: хост посылает MQTT beacon, включая retained-сообщение (с проверкой давности).
- Подключение гостя: отправляется discover, затем join; хост отвечает welcome, гость — ack.
- Публикация/подписка MQTT диагностируется настоящим echo-тестом, а не только открытым WebSocket.
- При пропущенных подтверждениях автоматический повтор отправки. Вернулся из фонового режима — повторный запрос.
- Сообщения сети из несовместимых версий не смешиваются: отдельный MQTT-канал 02.6.
- Увеличено ожидание появления хоста и добавлены подсказки для диагностики.
- MediaPipe локально на GitHub Pages (из 02.5) и старые игровые режимы сохранены.

## Обновление GitHub
1. **Заменить только корневой index.html** в репозитории AR на этот файл.
2. Существующий `.github/workflows/publish.yml` НЕ менять. Он уже настроен, его новая сборка автоматически подхватит index.html.
3. После зелёного deploy открыть на ОБОИХ телефонах https://zloirubl777.github.io/AR/?v=26 . Убедиться, что в меню написано 02.6.
4. Телефон 1: «Дуэль» → «Создать комнату». Дождаться «Комната ... ГОТОВА». Оставить вкладку открытой и телефон разблокированным.
5. Телефон 2: «Дуэль» → ввести новый шестизначный код → «Подключиться по коду».
6. Дождаться «Оба телефона соединены» на обоих. Затем «В бой».
7. Если нет соединения, нажать «Проверить доставку MQTT» на ОБОИХ телефонах и сравнить поля «MQTT доставляет сообщения», «Сигнал хозяина», «TX/RX». Снимки экрана этих блоков дадут конкретную причину.

## Ограничения
Это экспериментальный транспорт через публичные MQTT-брокеры. Доступность и доставка на конкретных сетях не гарантируются. Сами брокеры не приватны, поэтому не передавайте секретные данные. Видеопоток на MQTT не передаётся. ИИ распознаёт человека, но не обеспечивает доказательство идентичности или попадания через препятствия.
